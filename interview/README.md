# Interview QA 管理规范

## 目录定位

`interview/` 只保存两类内容：

1. 已经实际训练过的 interview QA；
2. 可以跨题复用的结构化思考方法。

不保存工程冲刺、项目状态、未训练的大题库或聊天流水。

## QA 文档结构

每份 QA 文档由两部分组成：

1. 顶部题目索引表：管理题目、分类和进度；
2. 下方知识卡：保存可以直接复习和口述的内容。

### 索引表格式

| ID | 分类 | 问题 | 状态 | 核心框架 |
| --- | --- | --- | --- | --- |
| AI-001 | 需求判断 | 如何判断 AI 助手需求是否值得做？ | 已完成 | 价值→适配→验证 |

索引表只用于快速找到题目，不承载完整答案。

### 知识卡格式

每道题只保留以下五部分：

```markdown
## AI-001：题目名称

### Q

### 结论

### 回答框架

### 关键判断

### 【简单版】标准答案
```

不保存原始聊天、逐轮点评、失分项、拓展知识和多个重复答案版本。

## 稳定 ID

- AI PM 使用 `AI-001`、`AI-002`……
- 普通 PM 使用 `PM-001`、`PM-002`……
- ID 创建后不随题目排序改变；
- 插入、移动或重新分类题目时不重新编号。

## 状态

只使用三种状态：

- `训练中`：已经开始回答，但还没有形成完整知识卡；
- `已完成`：已经形成五段知识卡；
- `待复习`：知识卡已经完成，但口头复述仍不熟练。

未开始训练的预设问题不进入 QA 文档。

## 新题处理流程

```text
提出新题
→ 检查是否与现有题重复
→ 分配稳定 ID，标记“训练中”
→ 用户初答、点评、追问和重答
→ 提炼五段知识卡
→ 标记“已完成”
```

如果新题与旧题高度重复，不新增 ID，而是局部补充旧题的关键判断或简单版答案。

## 更新规则

1. 新题在文档末尾追加知识卡，并在顶部索引增加一行；
2. 修改旧题时只更新对应知识卡，不重建整个文档；
3. QA 只保存提炼后的结论，不复制聊天流水；
4. 每题只保留一版简单标准答案；
5. 完成训练后再从“训练中”改为“已完成”；
6. 更新后检查 ID、索引、标题和链接是否一致。

## 文件编辑方法

### 首选：局部补丁

正常情况下，直接使用局部补丁更新目标文件，只修改对应索引行或知识卡，不覆盖整个文档。

### UNC 补丁桥失败时：WSL `git apply`

当 Windows 沙箱无法读取 `\\wsl.localhost` 下的已有文件时，使用以下安全流程：

```text
创建临时 .patch 文件
→ git apply --check 校验补丁
→ 校验通过后执行 git apply
→ 使用 git diff 核对实际改动
→ 删除临时 .patch 文件
```

执行规则：

1. 临时补丁只包含当前任务需要的局部修改；
2. `git apply --check` 失败时立即停止，不修改目标文件；
3. 校验通过后才能执行 `git apply`；
4. 应用后必须通过 `git diff` 检查目标、范围和内容；
5. 核对完成后删除临时补丁文件。

禁止为了绕过编辑错误而删除并重建整个 QA 文档，也不使用 `sed -i`、文本全量覆盖等难以审计的方式。
