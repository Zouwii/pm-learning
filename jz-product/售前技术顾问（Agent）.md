# 售前技术顾问（Agent）· 产品需求文档

---

## 1. 执行摘要

### 1.1 问题陈述

售前技术团队在日常工作中面临大量重复性咨询，主要包括三类核心问题：客户需求是否可落地（能不能做）、项目工时如何评估、设备方案如何选型。当前这些问题的解答高度依赖售前工程师的个人经验，存在以下痛点：

*   响应效率低：售前工程师需要在多个文档、表格和历史记录中查找信息，平均响应时间较长
    
*   标准不统一：不同售前工程师对同一问题的判断标准和结论不一致，影响客户信任度
    
*   经验难以沉淀：资深售前的经验知识依赖口口相传，人员变动导致知识流失
    
*   重复劳动严重：相似问题反复回答，高级售前工程师大量时间消耗在基础咨询上
    

### 1.2 解决方案

构建一个基于钉钉机器人的 AI 售前技术顾问 Agent，集成企业已有的结构化知识文档（FAQ、设备选型指南、工时评估对照表等），通过自然语言对话为内部售前/销售团队提供三大核心能力：能力可行性判断、工时评估、交互式设备选型。在无法自动应答时，Agent 能够无缝转接至人工售前专家。

### 1.3 成功标准（KPIs）

| 指标 | 目标值 | 衡量方式 | 优先级 |
| --- | --- | --- | --- |
| 自动应答率 | ≥ 60% | 无需转人工即完成解答的咨询占比 | P0 |
| 首响时间 | < 10秒 | 从用户提问到 Agent 给出首次有效回复的时间 | P0 |
| 答案准确率 | ≥ 85% | 人工抽检 Agent 回答与知识库内容的一致性和正确性 | P0 |
| 工时误差 | < 20% | Agent 评估工时与实际执行工时的偏差率 | P1 |
| 用户满意度 | ≥ 4.0/5 | 每次会话结束后的用户评分（钉钉消息卡片） | P1 |
| 知识库覆盖率 | ≥ 90% | 知识库能覆盖的售前问题类型比例 | P1 |

## 2. 用户体验与功能

### 2.1 用户画像

**主要用户：售前工程师**

日常工作中需要频繁回答来自销售、客户的各种技术可行性问题、设备选型方案和工时评估。对响应速度和准确度有较高要求，期望 Agent 能承担基础性、重复性的咨询工作，将精力集中在复杂项目和客户沟通上。

*   使用频率：每日多次
    
*   核心诉求：快速获取准确答案，减少重复查询文档的时间
    
*   痛点：知识分散在多个文档中，查找耗时；标准不统一，容易给出前后矛盾的回复
    

**次要用户：销售经理**

在客户现场或初次沟通时需要快速判断项目可行性、给出初步方案和预估工时。不直接操作设备选型，但需要了解方案可行性和大致工作量以便报价和排期。

*   使用频率：每周多次
    
*   核心诉求：销售场景下快速判断可行性，降低对售前工程师的依赖
    
*   痛点：售前工程师响应不及时时，无法独立判断项目可行性
    

### 2.2 核心用户故事

**US-01：能力可行性判断（能不能做）** 「P0」

作为售前工程师，我希望直接向 Agent 描述客户需求，Agent 能够基于知识库自动判断该需求是否可落地，并给出依据和参考案例，以便我快速回复客户或销售人员。

验收标准：

*   用户以自然语言描述客户需求，Agent 返回可行性结论（可落地/不可落地/需进一步确认）
    
*   返回结论须附带知识库中的依据来源（引用具体文档或条目）
    
*   对于知识库无法覆盖的问题，自动转人工售前专家处理
    
*   支持多轮对话追问，如「为什么不可落地」「有没有替代方案」
    
*   响应时间不超过 15 秒
    

**US-02：工时评估** 「P1」

作为售前工程师，我希望向 Agent 描述项目范围和需求，Agent 能够基于工时评估对照表给出预估工时，以便我快速完成报价和排期。

验收标准：

*   用户输入项目需求描述，Agent 基于工时评估对照表进行模糊匹配
    
*   返回预估工时范围（最乐观/最可能/最悲观）及匹配到的参考条目
    
*   当无法在对照表中找到匹配项时，自动转人工处理
    
*   支持按项目类型、规模等维度进一步细化工时预估
    
*   可导出评估结果为结构化数据供后续流程使用
    

**US-03：交互式设备选型** 「P0」

作为售前工程师，我希望通过多轮对话的方式引导 Agent 完成设备选型，Agent 基于设备选型指南逐步缩小推荐范围，给出最优方案。

验收标准：

*   Agent 基于设备选型指南，以交互式问答方式逐步收集用户需求参数
    
*   每轮交互聚焦一个维度（如场景、预算、性能要求等），引导用户做出选择
    
*   最终给出设备推荐方案，包含设备型号、关键参数、推荐理由
    
*   支持方案对比（最多对比 3 个方案）
    
*   当用户需求超出选型指南覆盖范围时，自动转人工处理
    
*   支持从任意步骤回溯重新选择
    

**US-04：经验提取与知识库更新** 「P2」

作为知识库管理员，我希望 Agent 能够从已完成的人工会话中自动提取新知识，经审核后更新到知识库，实现经验的持续沉淀。

验收标准：

*   Agent 自动分析人工会话记录，识别超出当前知识库覆盖范围的问答对
    
*   生成知识库变更建议（新增/修改/删除），以 Merge Request 形式提交审核
    
*   支持知识管理员对变更建议进行审核、修改和批准
    
*   变更批准后自动同步到知识库，并在后续对话中生效
    

### 2.3 非目标（Non-Goals）

*   不直接面向外部客户提供服务（本期仅服务内部团队）
    
*   不替代 CRM 或项目管理系统的功能（不处理报价单、合同等）
    
*   不进行设备采购下单或库存查询
    
*   不提供超出已有知识库范围的自主推理（严格基于文档知识回答）
    
*   不支持语音交互（本期仅文本对话）

## 3. AI 系统需求

### 3.1 核心 AI 能力

| 能力模块 | 描述 | 优先级 |
| --- | --- | --- |
| 意图识别 | 识别用户输入属于「能不能做」「评估工时」「设备选型」中的哪一类，并提取关键参数 | P0 |
| RAG 知识检索 | 基于用户问题从知识库中检索最相关的文档片段，支持语义匹配和关键词匹配 | P0 |
| 可控文本生成 | 基于检索到的知识生成结构化回答，包含结论、依据、建议等。严格基于检索内容，不凭空编造 | P0 |
| 多轮对话管理 | 维护会话上下文，支持追问、澄清、回溯等交互模式，尤其设备选型的多步骤引导流程 | P0 |
| 模糊匹配 | 工时评估场景中，将用户描述与对照表条目进行语义模糊匹配，输出最佳匹配及置信度 | P1 |
| 知识提取 | 从人工会话日志中自动发现新知识、识别过期条目、检测矛盾信息 | P2 |

### 3.2 工具与 API 需求

*   钉钉机器人 API：消息收发、Markdown 卡片渲染、交互式按钮、文件发送
    
*   知识库检索 API：企业已有结构化文档的索引和语义检索服务
    
*   LLM 推理 API：大语言模型推理服务，用于意图识别、文本生成、模糊匹配
    
*   会话存储：对话历史持久化存储，支持会话回溯和分析
    
*   人工转接服务：将无法自动处理的会话路由至指定人工售前专家
    

### 3.3 评估策略

建立分层评估体系，确保 Agent 输出质量可控：

**离线评估（上线前）**

*   构建 50+ 典型售前场景测试集，覆盖三大核心场景
    
*   答案准确性：人工标注标准答案，计算 Agent 回复的准确率（≥ 85%）
    
*   意图识别准确率：测试意图分类和参数提取的正确率（≥ 90%）
    
*   检索召回率：验证知识库检索的 Top-5 召回率（≥ 90%）
    

**在线评估（上线后）**

*   用户满意度评分：每次会话结束推送评分卡片（≥ 4.0/5）
    
*   转人工率：监控自动应答与转人工的比例，目标自动应答率 ≥ 60%
    
*   A/B 测试机制：支持不同 Prompt 版本的效果对比
    
*   异常检测：自动标记疑似幻觉、答案矛盾、知识过期的异常会话供人工审核

## 4. 技术规格

### 4.1 系统架构概览

| 层级 | 组件 | 职责 |
| --- | --- | --- |
| 消息接入层 | 钉钉 Bot Gateway | 接收钉钉群聊/单聊消息，解析用户意图后路由至 AI 引擎，将 AI 回复渲染为消息卡片推送回钉钉 |
| AI 引擎层 | Intent Router / RAG Engine / LLM Service | 意图识别与分发、知识库检索与排序、可控文本生成、多轮对话状态管理、人工转接决策 |
| 知识管理层 | Knowledge Base / Knowledge Extractor / MR Pipeline | 知识库构建与索引更新、从人工会话中提取新知识、生成 MR 供审核、审核通过后自动同步 |
| 数据存储层 | Session Store / Analytics DB / Vector DB | 对话历史持久化、用户反馈与评分存储、知识向量化存储与检索、运营数据看板 |

### 4.2 核心流程

**用户咨询流程：**

1.  用户在钉钉中 @机器人 发送咨询消息
    
2.  消息接入层接收消息，附加会话上下文（历史 5 轮对话）
    
3.  意图路由模块判断问题类型（能不能做 / 评估工时 / 设备选型 / 其他）
    
4.  RAG 引擎从知识库检索 Top-K 相关文档片段
    
5.  LLM 基于检索结果生成结构化回答
    
6.  置信度评估：高于阈值直接回复；低于阈值转人工
    
7.  消息卡片渲染并通过钉钉 Bot 推送给用户
    
8.  会话结束推送满意度评分卡片
    

**设备选型对话流程（特殊处理）：**

1.  识别用户进入设备选型意图后，启动状态机管理多轮对话
    
2.  基于设备选型指南定义决策树节点（场景 → 预算 → 性能 → 环境要求 → ...）
    
3.  每轮对话聚焦一个维度，提供可选项供用户点击或自然语言选择
    
4.  所有维度确认后输出推荐方案，支持方案对比和回溯重选
    

### 4.3 集成点

| 集成系统 | 方式 | 说明 |
| --- | --- | --- |
| 钉钉开放平台 | Webhook + API | 消息接收、消息发送、交互式卡片、群机器人能力 |
| 企业知识库系统 | API / SDK | 对接已有知识库（FAQ、设备选型指南、工时对照表等），支持增量索引更新和版本管理 |
| LLM 推理服务 | API | 接入大语言模型推理接口，需支持 Function Calling 和流式输出 |
| 向量数据库 | SDK | 存储知识库文档向量嵌入，支持语义检索和混合检索 |
| ~~钉钉通讯录~~ | ~~API~~ | ~~查询售前专家在线状态和组织架构，用于人工转接~~ |
| 代码仓库（Git） | API | 知识更新 MR 的创建、审核、合并流程，知识库变更版本管理 |

### 4.4 安全与隐私

*   所有用户对话数据加密存储，仅用于 Agent 能力提升分析
    
*   知识库访问权限与钉钉组织架构权限对齐，不同部门可见不同知识域
    
*   LLM 调用数据脱敏：发送给 LLM 的文本过滤客户敏感信息（公司名、联系方式等）
    
*   操作审计日志：记录所有知识库变更和 Agent 行为，支持事后追溯
    
*   API 鉴权：所有接口使用 OAuth 2.0 认证，通信全程 HTTPS

## 5. 风险与路线图

### 5.1 分阶段交付计划

**Phase 1 — MVP（核心验证）**

*   能力可行性判断（能不能做）：基于历史 FAQ 文档的 RAG 问答
    
*   基础转人工机制：知识库无法覆盖时 @指定售前专家
    
*   钉钉群聊机器人接入，支持自然语言单轮问答
    
*   交付人工抽检工具，支持在线标注和准确率统计
    
*   目标：验证 RAG 问答在售前场景的可行性，跑通从问题到答案的完整链路
    

**Phase 2 — 功能完善**

*   交互式设备选型：基于选型指南的多轮对话向导
    
*   工时评估：工时对照表模糊匹配 + 置信度输出
    
*   消息卡片升级：结构化回答渲染，支持方案对比展示
    
*   满意度评分卡片推送
    
*   运营数据看板（自动应答率、准确率、高频问题 TOP 10 等）
    

**Phase 3 — 智能增强**

*   经验自动提取：从人工会话中识别新知识，生成 MR 待审核
    
*   知识库自动更新：审核通过的变更自动同步到知识库
    
*   A/B 测试框架：支持不同 Prompt/模型版本的效果对比
    
*   多轮对话增强：支持更复杂的上下文理解和追问处理
    

### 5.2 技术风险与缓解措施

| 风险 | 描述 | 缓解措施 |
| --- | --- | --- |
| LLM 幻觉 | 大模型可能生成与知识库不符的回答，尤其边界情况 | 严格限制 LLM 仅基于检索结果回答；设置置信度阈值，低于阈值自动转人工；答案强制附带引用来源 |
| 知识库覆盖不足 | 初期知识库可能无法覆盖部分边缘场景，导致转人工率过高 | Phase 3 经验提取机制形成闭环；初期设置人工兜底 SLA（15 分钟内响应） |
| 领域术语理解偏差 | 售前场景存在大量行业专用术语和缩写，通用 LLM 可能理解错误 | 构建领域词库做 Prompt 增强；术语歧义时主动向用户澄清而非猜测 |
| 知识库过期 | 产品、价格、方案变更后知识库未及时更新，导致给出过时信息 | 知识库条目设置有效期标签，过期自动标记为待审核；Phase 3 经验提取可检测潜在矛盾信息 |
| 成本控制 | LLM 调用成本随使用量增长，需控制每个请求的 Token 消耗 | 设置单次回答 Token 上限；缓存高频问题答案；检索结果限制 Top-3 而非 Top-K；监控用量趋势 |
| 钉钉 API 限制 | 钉钉 Bot 消息频率限制、卡片格式兼容性、Webhook 超时等问题 | 实现消息队列缓冲 + 异步回复；多卡片分条发送避免内容截断；设置 Webhook 超时重试机制 |

## 附录：术语表

| 术语 | 说明 |
| --- | --- |
| RAG | Retrieval-Augmented Generation，检索增强生成，在生成回答前先从知识库检索相关文档片段作为上下文 |
| MR | Merge Request，代码/文档合并请求，用于知识库变更的审核流程 |
| 意图识别 | Intent Recognition，判断用户输入属于哪个业务场景并提取关键参数 |
| 转人工 | 当 Agent 置信度低于阈值或无法处理时，将对话路由给人工售前专家 |
| 置信度 | Confidence Score，Agent 对自身回答正确的信心评分，用于决定直接回复还是转人工 |
