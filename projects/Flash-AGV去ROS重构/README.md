# Flash AGV 去 ROS 重构项目

## 项目定位

这是一个以 **C++ 工程开发和机器人软件架构重构** 为核心价值的项目。

项目的重点不是定位或规划算法创新，而是将原本依赖 ROS 通信和生命周期的 AGV 功能模块，逐步重构为单进程、模块化、类型安全的 C++ 运行时，体现复杂机器人系统的架构设计与工程落地能力。

当前更准确的表述是 **渐进式去 ROS 重构**，不能表述为整套系统已经完全去 ROS。

## 核心模块

### State Manager

- 聚合整车状态、任务状态、位姿、速度、电量、载货、安全和定位信息；
- 通过 `StateClient` 约束模块间的状态读写边界；
- 使用回调、状态快照和信号黑板替代部分 ROS Topic/Service；
- 实现车辆状态迁移、错误分级、超时恢复和人工复位观察机制；
- 管理状态线程、并发访问和周期状态上传。

### Tag Localiser Manager

- 通过依赖注入接入 IMU、里程计和相机驱动；
- 使用类型化驱动订阅和缓冲区读取代替 ROS Subscriber；
- 将传感器数据转换后输入 `PerceptionNoRos`；
- 管理数据处理线程、CPU 绑核、启动回滚和资源释放；
- 主要用于独立调试及部分感知场景，并非当前整车主定位链路的唯一入口。

### Order Manager

- 负责 VDA5050 订单转换、增量订单拼接和路径裁断；
- 实现任务状态机以及任务暂停、恢复、取消和结果上报；
- 将导航目标由 ROS Action 调用改为进程内 `NavBase` 接口；
- 协调导航、二维码校验、取放货和充电等业务动作；
- 当前取放货、充电等 legacy async-service 业务仍依赖 ROS，因此属于部分去 ROS。

## 核心含金量

1. **C++ 中大型项目开发能力**：能够阅读、拆分和维护包含驱动、状态、定位、导航、通信及任务编排的复杂代码。
2. **模块与类架构设计能力**：通过接口抽象、依赖注入、客户端门面和职责分层降低模块耦合。
3. **并发与生命周期治理能力**：涉及线程启停、原子变量、互斥锁、回调、缓冲区、订阅关系和异常回滚。
4. **复杂任务编排能力**：处理增量订单、路径拼接、状态机、业务动作与导航动作之间的协同。
5. **机器人系统集成能力**：贯通传感器、定位、导航、整车状态、调度协议和底层驱动。
6. **存量架构迁移能力**：不是推倒重写，而是在保留旧业务兼容性的情况下逐步替换 ROS 运行时依赖。

## 当前评价

- 作为 C++／机器人软件工程项目：有较好的工程含金量；
- 作为模块化和架构设计案例：适合用于证明复杂系统设计能力；
- 作为算法项目：价值有限，重点并不在算法创新；
- 作为“完整去 ROS 项目”：目前证据不足，因为订单业务动作、rosbag 和部分构建配置仍保留 ROS 依赖。

当前可暂定为约 **7/10 的机器人 C++ 工程项目**。如果后续完成业务动作去 ROS、可复现构建、自动化测试及前后性能对比，项目说服力可以进一步提升。

## 简历表达草案

> 参与 Flash AGV 控制软件渐进式去 ROS 重构，围绕整车状态、二维码定位数据链和 VDA5050 订单导航链路，以类型化驱动订阅、状态黑板、进程内接口和依赖注入替代部分 ROS Topic/Action，完善状态聚合、故障恢复、任务状态机及增量订单执行，并为存量取放货业务保留兼容适配层。

## 使用边界

- 在未核验代码历史和个人实际贡献前，不写“独立完成”或“主导全系统去 ROS”；
- 后续需要区分原有业务代码、团队共同改造和个人实际完成的部分；
- 面试中应准确说明 `order_manager` 的 ROS 兼容链路，避免将“导航主链路去 ROS”扩大成“订单模块完全去 ROS”；
- 不编造启动时间、CPU、内存、延迟、覆盖率或实车运行效果。
