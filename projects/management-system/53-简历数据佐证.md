# 企业知识问答助手与 RAG 检索平台：简历数据佐证

> 用途：记录简历中每项数据的来源、计算公式、统计边界和可出示证据，作为简历修改与面试追问的统一口径。
>
> 原则：区分原始统计、实验实测、计算结果和规划外推；没有原始记录或明确分母的数据，不直接描述为已实现结果。

## 1. 当前简历表述

### 项目描述

前期基于钉钉平台上线知识助手，承接海外及工程团队的知识查询需求，但存在表格解析能力不足、召回文档不准确、外部链接文档无法纳入检索等问题。为此规划自建 RAG 检索平台并搭建企业知识问答助手“小迦”，提升知识检索效果与答案可追溯性。

### 工作内容

1. 分析钉钉知识助手的历史问答数据，识别表格解析、文档召回和外链知识接入等主要问题，据此确定自建 RAG 平台的首期改造范围与验收目标。
2. 规划知识接入、检索问答、来源引用和无答案拒答等核心功能，制定文档结构化与知识更新标准；聚焦海外及工程团队使用的研发共享知识库，完成 1,000+ 篇有效文档治理，打通知识同步、清洗、切分、索引和检索全链路。
3. 构建 52 道高频真实问题的 Golden Set 及产品评测体系，定义核心证据召回、问题命中及答案可追溯性等验收指标；通过检索策略优化，将 Recall@5 由 63% 提升至 87%，Hit@5 由 77% 提升至 88%。
4. 设计“FAQ 直答 + RAG 检索生成”的分层问答策略，高频标准问题由 FAQ 快速响应，复杂问题进入 RAG 链路；通过对照测试与 Bad Case 分析持续优化检索及问答策略。
5. 推动基于自建 RAG 的知识助手“小迦”上线运营，2026 年 Q2 累计完成 1,500+ 次问答，覆盖 70 余名海外及工程用户，平均问题回答时间约 8 秒，有效问题回复率达到 85%，已回复问题准确率达到 80%。

## 3. 检索实验佐证

### 3.1 原始问题集

当前已有历史实验使用 26 道独立问题：

| 问题类型 | 数量 |
| --- | ---: |
| 技术文档问题 | 10 |
| 会议纪要问题 | 7 |
| 跨文档问题 | 5 |
| 表格问题 | 4 |
| 合计 | 26 |

同一批 26 道问题分别运行 Baseline 和 Candidate，共形成 52 条离线评测记录。这里的“52 条评测记录”不等于“52 道独立问题”。

### 3.2 对照方案

- Baseline：全文检索 + 向量召回 + RRF 融合；
- Candidate：全文检索 + 向量召回 + RRF Top 20 + Cross-Encoder 重排 + Top 5。

### 3.3 结果计算

| 指标 | Baseline | Candidate |
| --- | ---: | ---: |
| 整体核心证据 Recall@5 | 29/46=63.04% | 40/46=86.96% |
| Hit@5 | 20/26=76.92% | 23/26=88.46% |
| 完整召回率 | 13/26=50.00% | 22/26=84.62% |
| MRR | 55.90% | 69.68% |
| nDCG@5 | 52.12% | 72.45% |

简历使用四舍五入口径：Recall@5 为 63% → 87%，Hit@5 为 77% → 88%。

## 4. 回答效果指标

### 4.1 有效问题回复率

建议公式：

`有效问题回复率 = 给出有效答案的问题数 ÷ 进入评测的有效问题总数`

需要先定义：

- 什么问题属于“有效问题”；
- 系统返回拒答、材料不足或要求澄清，是否计为回复；
- FAQ 与 RAG 是否合并统计；
- 分母来自 Golden Set、线上日志还是人工抽样集。

### 4.2 已回复问题准确率

建议公式：

`已回复问题准确率 = 人工审核正确的回答数 ÷ 系统已回复问题数`

“正确”至少应同时满足：

1. 核心结论与标准答案一致；
2. 关键事实没有明显遗漏或错误；
3. 引用内容能够支撑回答；
4. 不包含知识库证据无法支持的扩展结论。

如果回复率为 85%、已回复问题准确率为 80%，则端到端正确回答率为：

`85% × 80% = 68%`

该 68% 只用于理解指标关系，不在缺少真实分子、分母时写入简历。

## 6. 面试追问清单

按以下顺序逐项确认：

1. 52 道 Golden Set 是否已经形成 52 条独立问题记录，而不是由 26 题等比例外推？
2. 1,000+ 篇“有效文档”的去重、有效性与治理完成标准是什么？
3. 46 个必需核心证据是如何标注出来的，每题为什么是 1 个或 2 个？
4. Recall@5 和 Hit@5 的具体评测流程、标注人及复核方式是什么？
5. 85% 回复率的分子、分母分别是多少，“有效问题”如何定义？
6. 80% 准确率的分子、分母分别是多少，由谁按照什么标准审核？
7. 平均 8 秒的计时起点、终点和样本量是什么？
8. 1,531 次问答是否剔除了测试、失败和重复请求？
9. 79 名用户如何去重，海外、工程和研发用户分别有多少？
10. FAQ 与 RAG 的路由条件、效果指标和 Bad Case 分类是什么？

## 7. 当前风险提示

- 52 道问题与历史 26 道实测结果尚未完成证据对齐；
- 85% 回复率和 80% 已回复问题准确率尚缺少分子、分母及逐题记录；
- 平均 8 秒与用户范围需要统一线上统计口径；
- 不再使用缺少计算明细、且容易与回答准确率混淆的 Precision@5 84%；
- 对外讲述时必须区分检索命中、回答正确、正确拒答和用户采纳，不能互相替代。
