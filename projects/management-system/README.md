# 企业知识问答助手与 RAG 检索平台

## 项目定位

面向海外及工程团队的企业知识问答产品。项目先通过钉钉知识助手验证真实需求，再使用Dify完成RAG PoC，最终建设可独立评测、可接入自有产品的定制化RAG服务“小迦”。

产品以研发共享知识为基础，为用户提供产品信息、作业流程、文档知识和错误码等四类问答，并通过问题改写、FAQ直答、RAG检索生成、来源引用和无答案拒答控制回答质量。

## 项目时间线

| 阶段 | 时间 | 结果 |
| --- | --- | --- |
| 钉钉知识助手试用 | 2025年Q4 | 验证海外及工程团队的知识问答需求，收集真实问答与Bad Case |
| Dify PoC与自研建设 | 2026年Q1 | 验证定制化方案，完成自研RAG开发、验收并上线 |
| 交付使用与运营 | 2026年Q2 | 面向海外及工程团队正式使用，统计问答量、用户覆盖和回答质量 |

简历中的项目周期截至2026年3月，表示核心建设和上线阶段完成；2026年Q2的数据是交付使用后的运营结果。

## 核心业务问题

钉钉阶段验证需求后，真实Bad Case主要暴露出：

1. 合并单元格和多级表头等复杂表格解析后容易发生结构错乱；
2. 同一知识存在多个版本时，旧版本可能优先被召回；
3. 外部网页知识缺少统一抓取、Markdown治理和原始链接回溯能力；
4. 检索过程难以独立评测，也难以作为服务接入自有产品。

因此采用“Dify验证、自研落地”的路线。Dify用于低成本验证知识接入和问答链路，最终由研发建设定制化RAG应用链路。

## MVP方案

用户提问
→ 判断信息是否完整
→ 必要时追问并改写
→ FAQ匹配
→ 未命中则进入RAG检索
→ 混合召回、融合与重排
→ 判断证据和版本是否充分
→ 返回带来源答案或拒答
→ 记录反馈并进入Bad Case迭代

### 四类问题

| 类型 | 典型内容 | 处理方式 |
| --- | --- | --- |
| 产品信息 | 产品规格、参数、指令和规则 | FAQ优先，未命中进入RAG |
| 作业流程 | 部署、配置、维护和标定步骤 | FAQ优先，版本相关问题进入RAG |
| 文档知识 | 文档位置、版本差异和跨资料知识 | RAG检索生成并展示来源 |
| 错误码 | 错误解释和标准排查SOP | RAG提供知识指导，复杂诊断转人工 |

## 知识治理

首期聚焦海外及工程团队使用的研发共享知识，完成1,000+篇有效文档治理。

“有效文档”指来源和权限明确，正文非空、非重复，标题、章节、表格、链接和版本信息得到保留，且已完成清洗、切分、索引并能够参与检索的文档。

治理链路：

知识盘点
→ 同步
→ 解析、清洗和去重
→ 恢复标题与表格结构
→ 补充来源、权限和版本元数据
→ 切分与索引
→ 抽检和评测
→ 发布及持续更新

## 评测与结果

### Golden Set

简历口径为52道问题：

- 产品信息10道；
- 作业流程10道；
- 文档知识检索10道；
- 错误码与故障排查10道；
- 跨版本问题6道；
- 跨文档链路问题6道。

### 检索结果

- Recall@5：63% → 87%；
- Hit@5：77% → 88%。

当前可以直接追溯的历史实验使用26道独立问题。52道新结构与历史实验的证据关系、计算过程和安全讲法见 [05-简历数据说明.md](05-简历数据说明.md)。

### Q2运营结果

- 累计完成1,500+次问答，原始记录为1,531次；
- 覆盖70+名海外及工程用户，原始记录为79人；
- 问题回答率达到93%；
- 回答准确率达到85%。

使用量说明产品存在真实使用，但不能单独证明问题已经解决；回答质量仍需结合人工审核、来源引用、正确拒答和Bad Case判断。

## 我的核心工作

1. 分析钉钉知识助手历史问答和Bad Case，确定用户、问题类型和MVP范围；
2. 基于Dify搭建PoC，验证知识接入、检索生成、来源引用和无答案拒答；
3. 设计问题改写、FAQ直答与RAG检索生成的分层问答策略；
4. 制定有效文档、结构化、版本、来源和权限标准，推动1,000+篇文档治理；
5. 构建Golden Set和评测体系，通过Bad Case推动检索与重排优化；
6. 协调业务、知识负责人和研发完成Q1上线，并在Q2跟踪交付使用与运营效果。

## 当前证据边界

- 1,000+篇文档需要保留最终处理清单和状态字段；
- 52道独立Golden Set仍需补齐逐题问题、答案和核心证据；
- 历史检索结果来自26道独立问题，不能冒充52道新测试结果；
- 93%回答率和85%准确率仍需保留分子、分母和审核记录；
- 1,500+次问答和70+用户证明真实使用，不能替代自助解决率和问题解决时间。
