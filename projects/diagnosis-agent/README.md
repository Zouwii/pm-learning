# Diagnosis-Agent

## 项目定位

面向 AGV 应用工程师的技术支持诊断 Agent。产品将错误码知识和高频故障排查经验转化为标准化、可执行、可追踪的诊断能力，辅助完成问题理解、诊断路径选择、分步排查和模块归属收敛。

核心边界：Agent 不替研发修复 Bug；证据不足、流程未覆盖或需要高风险现场操作时，由人工接管。

## 简历4主线

1. 复盘历史现场问题并访谈应用工程师，识别高频重复诊断场景；
2. 将首期 MVP 收敛为“错误码诊断＋高频故障诊断”双路径；
3. 采用 Workflow 与 Agent 协同：Agent 负责理解和路由，Workflow 负责执行和留证；
4. 制定知识结构与审核标准，协同沉淀 150 篇错误码排查文档和 10 套高频诊断流程；
5. 使用 50 个真实 Case 开展灰度验证，根据 Bad Case 迭代材料校验、进度展示、证据追溯和人工接管。

## 结果口径

- 50 个目标 Case 中，40 个收敛至唯一责任模块，收敛率为 80%；
- 40 个已收敛 Case 中，37 个判断正确，准确率为 92.5%，简历概括为 92%；
- 典型软件故障初筛和模块转交时间由约 60 分钟缩短至约 10 分钟，降低 80%+；
- 季度节省约 95 小时为测算值，不是埋点累计值；
- “收敛”指完成模块归属判断和证据化交接，不代表 Bug 已修复。

## 团队与个人职责

| 角色 | 主要职责 |
| --- | --- |
| 产品经理 | 用户研究、MVP 范围、双路径方案、知识标准、交互、安全边界和验收 |
| 算法/AI 研发 | Agent 框架、场景识别、工具编排和结果生成 |
| 平台开发 | Case 管理、页面交互、权限与系统集成 |
| 领域研发 | 错误码知识编写、技术审核和复杂 Case 复核 |
| 应用工程师 | 高频流程共创、真实 Case 验证和反馈 |

正式讲述时，重点说明个人主导的产品判断和推动工作，不把团队完成的算法、工具或领域知识全部表述为个人开发。
