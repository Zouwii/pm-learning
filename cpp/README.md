# 软件工程 / C++ 工作沉淀

> 这不是临时刷题目录，而是我的软件工程退路线：把当前公司两年的真实开发工作变成可验证、可复述、可迁移的职业资产。

## 目标

1. 还原我从 2024 年 10 月至今做过的软件工作；
2. 说清楚每个项目中我解决的问题、承担的边界和技术决策；
3. 用代码、Git、文档和真实 Case 支撑结论；
4. 找出 C++ 基础、工程能力和面试表达上的缺口；
5. 最终产出一版软件工程简历和一套项目面试讲述。

## 待沉淀的三个 C++ 工作方向

以下范围由本人确认，具体职责、项目时间、技术细节和交付结果后续逐项补充并核验：

1. [`nav-manager`](./nav-manager/README.md)；
2. [`enbody` 中的 `embodied-app`](./embody/README.md)；
3. [`flash-agv-develop-laser_agv`](./flash-agv/README.md)。

## 当前已确认的主线

```text
机器人本体任务决策层开发
        ↓
跨模块接口、状态及时序协作
        ↓
到点自学习：车端 C++ + 服务端 Go/Vue/MySQL
        ↓
数据采集、补偿选择、目标应用、异常保护与版本兼容
        ↓
逐步扩展到需求导入、产品化和 AI PM
```

目前最强的软件项目证据来自“到点自学习”：我跨 `nav-manager` 和 `nav-application` 完成车端与服务端闭环。其中 C++ 侧主要是自学习数据采集、补偿解析与选择、目标位姿应用、状态管理、有效性保护、热更新和版本兼容。

这只是当前起点，不代表两年工作的完整范围。其他任务、线上问题、重构和交付需要继续从 Git 与本人记忆中补齐。

## 整理顺序

1. 先在时间线中列出做过的功能、故障和交付，不急着润色；
2. 每次选择一个重要项目，用复盘模板回答问题；
3. 在证据索引中补上对应代码、提交或文档；
4. 将验证后的事实映射到能力地图；
5. 最后再生成简历要点和面试答案。

## 事实与保密规则

- 区分“独立负责、主导、共同完成、参与、了解”；
- 区分“正式上线、现场试用、实验分支、规划中”；
- 没有可靠数据时，不写“提升 X%”“覆盖 X 台”等数字；
- 提交数只能证明参与深度，不能直接证明业务价值；
- 不保存客户名称、账号、密码、内网地址、未公开源码和原始生产数据；
- 面试材料中的系统名、现场名和数据按需要脱敏。

## 完成标准

- 一页软件工程简历可以独立投递；
- 能用 30 秒和 2 分钟讲清至少两个项目；
- 每个关键结论都能找到证据或明确标记为本人确认；
- 能回答 C++ 岗位对项目深挖、故障排查、设计取舍和基础知识的追问；
- 知道下一阶段该补哪些知识，而不是无边界刷题。
