# 任务引擎：代码索引（初版）

> 源码仓库：`flash-agv-develop-laser_agv`。本页记录当前代码的模块对应关系；个人负责范围、开发时间和实际交付版本仍待结合 Git 提交与本人确认。

## 主调用链

```text
RCS / VDA5050 OrderMessage
  → CommAdapterManager 接收订单并调用 TaskManager::taskInit
  → TaskManager::taskTransform：订单节点、边转换为 TaskPath
  → NavStitcher::stitchOrders：与已有路径拼接
  → TaskManager::taskProcess / executeTask：执行循环
  → NavPruner::pruneOrders：按当前位置和路径约束裁断
  → TaskManager::preprocessGoal / sendGoal：下发导航目标
  → TaskManager::publishTaskStatus → StateManager → CommAdapterManager::uploadStatus
```

## 功能与代码对应

| 功能 | 主要代码入口 | 当前读到的行为 |
| --- | --- | --- |
| 订单接收与 VDA5050 通信 | `src/communication/comm_adapter_manager.cpp` 的 `initializeTransport`、`activateBusinessHandlers`、`uploadStatus`、`buildStateMessage` | 通过 `comm_adapter::CommAdapter` 注册 `OrderMessage` 回调，交给 `TaskManager::taskInit`；状态快照转换为 `StateMessage` 后上报。配置中的协议版本为 `VDA5050_V2`，任务和状态主题分别为 `/order`、`/state`。底层 MQTT 与协议序列化由 `comm_adapter` 依赖提供，当前仓库内看到的是接入层。 |
| 订单转换与任务协调 | `src/order_manager/task_manager.cpp` 的 `taskTransform`、`taskInit`、`taskProcess`、`executeTask` | 检查节点与边数量，将订单转为内部路径；管理任务状态、执行循环、导航目标和结果。 |
| 任务拼接 | `src/order_manager/stitcher.cpp` 的 `stitchOrders`、`stitchWithLastPath`、`stitchWithoutLastPath` | 查找新旧路径的重叠段，保留旧路径并追加新点；无重叠时还检查端点相同或 `order_update_id` 连续等条件。 |
| 路径裁断 | `src/order_manager/pruner.cpp` 的 `pruneOrders`，以及 `task_manager.cpp` 的 `preprocessGoal` | 根据当前路径位置、行驶类型、放行状态、轨迹等条件计算裁断区间；任务管理器据此生成下发给导航模块的路径段。 |
| 异常与取消 | `include/order_manager/task_manager.h` 的 `handleException`，`src/order_manager/task_manager.cpp` 的 `taskInit`、`executeTask`、`cancelTask`、`taskProcess`，`include/order_manager/utils/fsm_task.hpp` | 转换、拼接、预处理、目标下发等失败时上报错误并切换任务状态；车辆故障或取消时中止导航，取消任务还会清理关联业务动作。错误记录经状态管理模块进入状态上报。 |
| 任务状态上报 | `task_manager.cpp` 的 `publishTaskStatus`、`src/state_manager/state_manager.cpp` 的 `tick`、`comm_adapter_manager.cpp` 的 `uploadStatus` | 形成导航与节点动作状态，写入状态管理器；周期性生成快照并通过通信适配层上传。 |
